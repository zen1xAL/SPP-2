# Лабораторная работа №3

## Постановка задачи
Дополнить приложение из лабораторной работы №2:

1. **Модель доступа на основе временных ключей**:
   - Реализовать ролевую модель доступа (RBAC) как минимум с 3 ролями:
     - `admin` (Администратор) – полный доступ к управлению задачами, ролями и активными сессиями.
     - `manager` (Менеджер / Редактор) – создание, редактирование задач, изменение статусов и загрузка/удаление файлов.
     - `viewer` (Наблюдатель) – доступ только для чтения (просмотр задач и скачивание файлов).
   - Аутентификация на основе временных ключей (Access Token с ограниченным сроком действия + сессионный механизм).

2. **Семантика стандартов HTTP**:
   - Строгое соответствие кодов состояния RFC 7231 / RFC 9110:
     - `200 OK`, `201 Created`, `204 No Content`
     - `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict`, `422 Unprocessable Entity`, `429 Too Many Requests`, `500 Internal Server Error`.
   - Единообразный JSON-формат ошибок.

3. **Безопасность учетных записей**:
   - Защита от подбора учетных данных (Brute-Force Rate Limiting): лимит неудачных попыток входа с блокировкой и возвратом HTTP 429 Too Many Requests.
   - Контроль активных подключений: отслеживание сессий пользователя (IP, User-Agent, дата входа) и возможность отзыва (завершения) сессий.
   - Восстановление доступа через электронную почту: генерация временного одноразового токена сброса пароля со сроком жизни и отправка ссылки для смены пароля.

4. **Структурированное логирование**:
   - Логирование в формате JSON с метаданными: временная метка, уровень логирования, корреляционный идентификатор запроса (Request ID), HTTP-метод, маршрут, статус, время ответа, IP-клиента и идентификатор пользователя.

5. **Автоматизированный процесс проверки кода (CI)**:
   - Конфигурация GitHub Actions CI для автоматического прогона линтинга, статической типизации, юнит/интеграционных тестов и сборки при изменениях.
