# Лабораторная работа №5

## Постановка задачи
Разработать клиент-серверное веб-приложение с использованием технологии **GraphQL**.

### Основные требования:
1. **Взаимодействие backend и frontend только через GraphQL**:
   - Все операции получения, изменения данных и уведомлений в реальном времени должны производиться исключительно через GraphQL-эндпоинт (Queries, Mutations, Subscriptions). REST-маршруты для передачи клиентских данных исключены.
2. **Автоматизированный сбор данных минимум из 3 источников**:
   - Реализовать автоматизированную подсистему агрегации данных из не менее чем трех разнородных источников (внешние REST API, публичные новостные/RSS-ленты, локальные высокообъемные генераторы).
   - Суммарный объем хранимых и обрабатываемых данных должен составлять **не менее 10 000 записей** с высокой степенью разнообразия.
3. **Различные типы операций, вложенность и динамическое формирование**:
   - Поддержка операций чтения (`Query`), изменения данных (`Mutation`) и потоковых подписок в реальном времени (`Subscription`).
   - Наличие многоуровневой иерархической вложенности связных сущностей (не менее 3–4 уровней).
   - Динамическое формирование структуры запросов на стороне клиента.
4. **Фильтрация, сортировка, поиск и пагинация**:
   - Реализация полнотекстового поиска по каталогу.
   - Мультикритериальная фильтрация по категориям, числовым диапазонам и рейтингу.
   - Сортировка по различным полям в прямом и обратном порядке.
   - Пагинация данных (поддержка спецификации Relay Cursor Connections и смещения Offset).
5. **Высокая производительность и отказоустойчивость**:
   - Применение паттерна **DataLoader** для полного устранения проблемы $N+1$ запросов при разрешении связей.
   - Индексация базы данных для быстрого поиска по десяткам тысяч записей.
   - Защита от сбоев внешних источников (graceful degradation / fallback).

### Дополнительные требования (на оценку 8–10):
1. **Контроль нагрузки, мониторинг и трассировка**:
   - Анализ и ограничение сложности запросов (**Query Complexity & Depth Limiting**) для защиты сервера от перегрузки и DoS-атак глубокими вложенными запросами.
   - Трассировка времени выполнения отдельных резолверов и мониторинг метрик производительности сервера.
2. **GraphQL Federation и распределенная архитектура**:
   - Построение схемы на основе спецификации **GraphQL Federation** (декомпозиция на независимые логические подграфы: Каталог, Отзывы, Складские остатки с использованием директив `@key` и расширений типов, объединенные в единый суперграф через Gateway).
