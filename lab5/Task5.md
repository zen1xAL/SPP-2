# Лабораторная работа №5: Клиент-серверное приложение на базе GraphQL & Apollo Federation

## Постановка задачи
Разработать клиент-серверное приложение на базе технологии **GraphQL** с поддержкой распределенной архитектуры **GraphQL Federation**.

### Основные требования:
1. **Взаимодействие backend и frontend только через GraphQL**:
   - Все запросы данных, мутации и подписки в реальном времени производятся исключительно через единый GraphQL-эндпоинт (`/graphql`).
2. **Автоматизированный сбор данных минимум из 3 источников**:
   - Источник 1: Внешний REST API товаров (DummyJSON / FakeStore).
   - Источник 2: Новостной / RSS / JSON поток технических и товарных обзоров.
   - Источник 3: Локальный высокообъемный генератор срезов цен и отзывов.
   - Общий объем данных в базе: **более 10 000 записей**.
3. **Различные типы операций, вложенность и динамическое формирование**:
   - Реализация `Query`, `Mutation` и `Subscription` (`graphql-ws`).
   - Иерархическая вложенность до 3–4 уровней: `Category -> Product -> Reviews -> Author`, `Product -> PriceHistory`, `Product -> WarehouseStock`.
   - Динамический конструктор запросов (Query Studio) на клиенте.
4. **Фильтрация, сортировка, поиск и пагинация**:
   - Полнотекстовый поиск с автодополнением/debounce.
   - Фильтры по категориям, ценовым диапазонам и рейтингу.
   - Сортировка по цене, рейтингу, названию (ASC/DESC).
   - Пагинация: Relay Cursor Connections (`edges`, `node`, `pageInfo`) и классический Offset.
5. **Высокая производительность и отказоустойчивость**:
   - Батчинг запросов через **DataLoader** (устранение проблемы $N+1$).
   - Индексированная база данных SQLite (WAL-режим) для миллисекундных выборок из 10 000+ строк.
   - Graceful fallback при сбоях внешних API.

### Дополнительные требования (на оценку 8–10):
1. **Контроль нагрузки, мониторинг и трассировка**:
   - **Query Complexity & Depth Limiting**: автоматический расчет стоимости запроса и ограничение предельной глубины.
   - **Tracing Plugin**: замер времени выполнения отдельных резолверов и мониторинг метрик сервера.
2. **GraphQL Federation и распределенная архитектура**:
   - Декомпозиция схемы на 3 подграфа (`Products`, `Reviews`, `Inventory`) на базе `@apollo/subgraph` с объединением в единый суперграф через `@apollo/gateway`.
