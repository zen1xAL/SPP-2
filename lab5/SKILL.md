# GraphQL Testing & Federation Verification Skill

Данный навык определяет регламент всестороннего тестирования и валидации клиент-серверного GraphQL-приложения, построенного на архитектуре Apollo Federation с контролем сложности запросов, батчингом DataLoader и подписками в реальном времени.

---

## Когда применять этот навык

Активируйте данный навык при:
* Проверке выполнения требований Лабораторной работы №5 («Лабораторная работа по GraphQL»).
* Валидации композиции схемы Apollo Federation и корректности разрешения внешних сущностей (`@key`, `@extends`).
* Проверке устранения проблемы $N+1$ запросов с помощью DataLoader.
* Тестировании защиты сервера от перегрузки (Query Complexity и Depth Limiter).
* Проверке пагинации по спецификации Relay Cursor Connections (`edges`, `node`, `pageInfo`).
* Верификации объема базы данных (контроль наличия не менее 10 000 записей).
* Верификации GraphQL-подписок через протокол WebSocket (`graphql-ws`).

---

## Предварительные требования

* Установленный Node.js (версия 20+ LTS) и пакетный менеджер `npm`.
* Локальная база данных SQLite (`lab5/data/marketplace.db`), созданная и заполненная сборщиком данных.
* Установленные зависимости проекта в директории `lab5`:
  * `@apollo/server`, `@apollo/subgraph`, `@apollo/gateway`, `graphql`, `dataloader`, `vitest`.

---

## Пошаговый алгоритм действий

1. **Проверка объема данных (Data Volume Check)**:
   * Выполнить верификационный запрос к базе данных или запустить тест `volume.test.ts`.
   * Убедиться, что общее число строк в связанных таблицах (`products`, `reviews`, `price_history`, `stocks`) превышает **10 000 записей**.

2. **Верификация схемы Apollo Federation**:
   * Проверить композицию подграфов `products`, `reviews`, `inventory` в единый суперграф.
   * Выполнить кросс-подграфовый запрос: запросить `Product` с вложенными полями `reviews` (из подграфа отзывов) и `inventory` (из подграфа складов) за один GraphQL-запрос.
   * Убедиться, что резолвинг ссылок `@key` отрабатывает без ошибок.

3. **Верификация DataLoader (N+1 Prevention Check)**:
   * Запустить тест `dataloader.test.ts`.
   * При запросе списка из $K$ товаров с их вложенными отзывами и остатками счетчик вызовов SQL-запросов к таблицам `reviews` и `stocks` должен быть равен **ровно 1** (батчинг по списку `product_ids`).

4. **Верификация контроля сложности (Query Complexity & Depth Limiting)**:
   * Запустить тест `complexity.test.ts`.
   * Выполнить нормальный запрос (сложность < порога) – статус `200 OK`.
   * Выполнить искусственно раздутый циклический или глубокий запрос (глубина > 6 или стоимость > 500) – запрос должен быть отклонен на этапе валидации до исполнения резолверов с ошибкой `GRAPHQL_VALIDATION_FAILED`.

5. **Верификация пагинации Relay**:
   * Запустить тест `pagination.test.ts`.
   * Проверить структуру ответа: наличие `edges`, `node`, `cursor`, `pageInfo { hasNextPage, hasPreviousPage, startCursor, endCursor }`.
   * Проверить передачу аргументов `first` и `after`, убедиться в отсутствии дублирования записей при переходе по страницам.

6. **Проверка типизации TypeScript**:
   * Выполнить проверку компилятором TypeScript в строгом режиме: `npm run typecheck`.

---

## Шаг верификации результата

Команда терминала для запуска полного тестового пайплайна:

```bash
cd lab5
npm run typecheck
npm test
```

Критерии успешности:
* `npm run typecheck` завершается с кодом `0` и отсутствием ошибок типов.
* Все 6 тест-сьютов Vitest (`federation`, `dataloader`, `complexity`, `pagination`, `volume`, `subscriptions`) завершаются со статусом `PASS`.
* База данных содержит $\ge 10\,000$ валидных записей.
* В консоли сервера отсутствуют необработанные исключения.
