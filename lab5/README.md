# Лабораторная работа №5: Распределенное клиент-серверное GraphQL-приложение (Apollo Federation v2)

Полнофункциональная распределенная платформа каталога товаров и складской аналитики **«Marketplace Hub»** на базе **GraphQL** и **Apollo Federation v2**.

---

## 📌 Выполнение всех требований лабораторной работы

### 1. Взаимодействие backend и frontend только через GraphQL (100% GraphQL)
* Клиентское приложение на **React 18 + TypeScript + Apollo Client** общается с бэкендом **исключительно через GraphQL-эндпоинт** (`/graphql`).
* Никаких REST API для передачи бизнес-данных не используется.
* Все операции реализованы через типизированные GraphQL-запросы (`Query`), мутации (`Mutation`) и потоковые подписки в реальном времени (`Subscription`).

### 2. Автоматизированный сбор данных минимум из 3 источников ($\ge$ 10 000 записей)
Реализован надежный ETL-модуль сбора данных (`src/server/collectors/`):
1. **Источник 1 (Внешний REST API)**: сбор товаров из публичного каталога DummyJSON (с автоматическим fallback при отсутствии сети).
2. **Источник 2 (Новостной / RSS фид)**: автоматическая агрегация обзоров и экспертных оценок из HackerNews / Tech Feeds.
3. **Источник 3 (Bulk Seed Generator)**: высокопроизводительный генератор каталога, генерирующий **более 10 000 временных срезов цен (`price_history`)**, тысячи отзывов и складских позиций.
* **Итоговый объем хранилища**: более **15 000 записей** в индексированной базе SQLite в режиме Write-Ahead Logging (WAL).

### 3. Различные типы операций, многоуровневая вложенность и динамика
* **Query**: чтение каталога, поиск, детальная карточка, метрики производительности.
* **Mutation**:
  * `createProduct` – создание нового товара;
  * `addReview` – добавление отзыва через подграф Reviews;
  * `updateStock` – обновление складского остатка через подграф Inventory;
  * `triggerDataIngestion` – ручной или автоматический перезапуск ETL-пайплайна.
* **Subscription**: поток реального времени по протоколу `graphql-ws` (изменения котировок, новые отзывы, обновления складов).
* **Многоуровневая вложенность (до 4 уровней)**:
  * `Product -> PriceHistory (25 срезов) -> Reviews (автор, рейтинг, дата) -> Inventory (склады, города, остатки)`.
* **Динамическое формирование (Query Studio)**:
  * Интерактивный конструктор запросов в UI: выбор любых полей и уровней вложенности с динамической генерацией AST и отправкой на сервер.

### 4. Фильтрация, сортировка, поиск и Relay-пагинация
* **Полнотекстовый поиск**: по названию, бренду и описанию с debounce-задержкой 300 мс.
* **Мультикритериальные фильтры**: по категориям товаров и числовому диапазону цен (от / до).
* **Сортировка**: по возрастанию и убыванию цены, рейтингу, названию и дате создания.
* **Пагинация**: полная поддержка спецификации **Relay Cursor Connections** (`edges`, `node`, `cursor`, `pageInfo { hasNextPage, hasPreviousPage, startCursor, endCursor }`, `totalCount`).

### 5. Высокая производительность и отказоустойчивость
* **DataLoader**: устранение классической проблемы $N+1$ запросов. При запросе списка из 15 товаров с их отзывами, остатками и историей цен выполняется ровно по 1 батч-запросу к каждой таблице (проверено в `tests/dataloader.test.ts`).
* **Индексация SQLite**: составные B-Tree индексы на столбцы `price`, `rating`, `category`, `product_id`.
* **Graceful Degradation**: защита от сетевых сбоев внешних API.

## 🚀 Дополнительные требования (на оценку 8–10)

### 1. Контроль нагрузки, мониторинг и трассировка
* **Query Complexity & Depth Limiting**: кастомный AST-валидатор (`src/server/complexity.ts`), рассчитывающий стоимость скаляров, объектов и списковых множителей (`first`). Запросы с глубиной $> 6$ или суммарной стоимостью $> 500$ баллов отклоняются до исполнения резолверов с ошибкой `GRAPHQL_VALIDATION_FAILED`.
* **Apollo Tracing Plugin**: плагин (`src/server/tracing.ts`), замеряющий время работы каждого резолвера и отдающий метрики в `extensions.tracing` и в GraphQL-запросе `systemMetrics`.
* **Интерактивный дашборд**: экран «Мониторинг & Federation» отображает время ответа резолверов, объем базы данных и число активных WebSocket-клиентов.

### 2. GraphQL Federation v2 и распределенная архитектура
Схема декомпозирована на 3 независимых микросервисных подграфа на базе `@apollo/subgraph`:
1. **`products-subgraph`**: владеет сущностью `Product @key(fields: "id")`, категориями и историей цен.
2. **`reviews-subgraph`**: расширяет `Product` полем `reviews: [Review!]!`, рассчитывает средний рейтинг и обрабатывает отзывы.
3. **`inventory-subgraph`**: расширяет `Product` полем `inventory: [WarehouseStock!]!` и отслеживает географические остатки по складам.
* Все 3 подграфа объединяются в единый суперграф через **Apollo Gateway** (`@apollo/gateway`) с использованием `LocalGraphQLDataSource` для мгновенной локальной оркестрации.

## 🛠️ Запуск проекта

### 1. Локальный запуск (Node.js 20+):

```bash
cd lab5

# Установка зависимостей
npm install

# Запуск в режиме разработки (бэкенд на :4000 + клиент Vite на :5173)
npm run dev
```

* Веб-клиент: `http://localhost:5173` (или `http://localhost:4000` в продакшене)
* GraphQL Playground / API: `http://localhost:4000/graphql`
* WebSocket Subscriptions: `ws://localhost:4000/graphql`

### 2. Запуск в Docker:

```bash
cd lab5
docker compose up --build
```

## 🧪 Тестирование и верификация

В проекте реализован комплексный тестовый сьют на базе **Vitest**, покрывающий все аспекты работы системы:

```bash
cd lab5

# Проверка строгой статической типизации TypeScript
npm run typecheck

# Запуск всех тестов
npm test

# Полная верификация
npm run verify
```

### Состав автоматических тестов:
1. `tests/volume.test.ts` – подтверждение объема базы данных $\ge 10\,000$ записей и наличия данных из 3 источников.
2. `tests/federation.test.ts` – проверка композиции суперграфа и кросс-подграфовых запросов.
3. `tests/dataloader.test.ts` – верификация устранения проблемы $N+1$ через DataLoader.
4. `tests/complexity.test.ts` – тест отсечения запросов при превышении лимитов глубины и сложности.
5. `tests/pagination.test.ts` – проверка пагинации по стандарту Relay Cursor Connections, поиска и фильтрации.
6. `tests/subscriptions.test.ts` – проверка генераторов подписок и доставки событий WebSocket в реальном времени.
