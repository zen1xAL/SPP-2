# Разбор файла: src/server.ts

**Путь к файлу**: [src/server.ts](file:///d:/SPP/7sem/SPP/src/server.ts)  
**Роль в архитектуре**: Точка входа приложения (Application Entry Point) и управление жизненным циклом сетевого сервера (Runtime Lifecycle & Graceful Shutdown).

---

## 1. Концептуальное и архитектурное назначение

Файл [src/server.ts](file:///d:/SPP/7sem/SPP/src/server.ts) является исполнимым скриптом верхнего уровня. Его ключевые задачи:
1. **Инициализация конфигурации окружения**: подключение переменных из файла `.env` в глобальный объект `process.env`.
2. **Инстанцирование приложения**: вызов фабрики `createApp()` из модуля [src/app.ts](file:///d:/SPP/7sem/SPP/src/app.ts), которая инкапсулирует конфигурацию Express, роутов и зависимостей.
3. **Открытие сетевого сокета (Listen)**: привязка Node.js HTTP-сервера к заданному TCP-порту.
4. **Корректная обработка сигналов ОС (Graceful Shutdown)**: перехват сигналов завершения процесса (`SIGINT`, `SIGTERM`), освобождение ресурсов и закрытие сетевых соединений без обрыва активных запросов пользователей.

---

## 2. Ключевые концепции Node.js и особенности среды выполнения

### 2.1. Side-effect Import в ECMAScript Modules (ESM)
Строка `import 'dotenv/config';` является так называемым *импортом с побочным эффектом* (side-effect import). При запуске модуля движок V8 исполняет код библиотеки `dotenv` еще до выполнения любых локальных выражений. Библиотека считывает файл `.env` из корневой папки процесса (`process.cwd()`), парсит ключ-значения и мутирует системный объект `process.env`.

### 2.2. Event Loop и сетевой сокет (libuv TCP listen)
Вызов `app.listen(PORT, cb)` внутри Express делегируется нативному модулю `node:http`. На уровне системного ядра через библиотеку **libuv** создается TCP-сокет, вызываются системные вызовы `bind()` и `listen()`. Пока сокет открыт, в Event Loop Node.js зарегистрирован активный обработчик (active handle), который не позволяет процессу завершиться самостоятельно.

### 2.3. Механизм Graceful Shutdown и сигналы POSIX
В современных серверных средах (Docker, Kubernetes, systemd) завершение процесса происходит не мгновенно через жесткий `SIGKILL`, а через мягкий запрос на завершение:
- `SIGINT` (Signal Interrupt) – посылается при нажатии клавиш `Ctrl + C` в консоли.
- `SIGTERM` (Signal Terminate) – стандартный сигнал завершения от диспетчера процессов контейнера.

Метод `server.close(callback)` прекращает прием новых входящих TCP-соединений и ожидает завершения обработки текущих активных HTTP-транзакций, после чего вызывается коллбэк, где мы вызываем `process.exit(0)`.

## 3. Построчный разбор кода

### Строки 1–2: Директивы импорта
```typescript
import 'dotenv/config';
import { createApp } from './app.js';
```
- **Строка 1**: Загружает переменные окружения в `process.env`.
- **Строка 2**: Импортирует фабричную функцию `createApp` из модуля [src/app.ts](file:///d:/SPP/7sem/SPP/src/app.ts). Обратите внимание на расширение `.js` в пути: в стандарте Node.js ECMAScript Modules (ESM) указание явного расширения `.js` обязательно, так как TypeScript при компиляции не переписывает пути импортов.

### Строки 4–5: Конфигурация порта и сборка приложения
```typescript
const PORT = Number(process.env.PORT || '3000');
const app = createApp();
```
- **Строка 4**: Читает значение `PORT` из `process.env`. Если переменная не определена, берется дефолтное строковое значение `'3000'`. Функция `Number()` преобразует строку в примитивный тип `number`, гарантируя строгую типизацию порта для сетевого API Node.js.
- **Строка 5**: Вызывает фабрику `createApp()`, получая сконфигурированный экземпляр `Application` фреймворка Express со всеми подключенными middleware, хранилищами и контроллерами.

### Строки 7–13: Запуск HTTP-сервера и логирование
```typescript
const server = app.listen(PORT, () => {
  console.log(`====================================================`);
  console.log(`🚀 Сервер задач (SSR) успешно запущен на порту ${PORT}`);
  console.log(`🌐 Доступен по адресу: http://localhost:${PORT}`);
  console.log(`⚙️  Режим: ${process.env.NODE_ENV || 'development'}`);
  console.log(`====================================================`);
});
```
- **Строка 7**: `app.listen(PORT, callback)` создает экземпляр `http.Server` и привязывает его к порту. Возвращаемый объект `server` сохраняется в константу для последующего управления жизненным циклом.
- **Строки 8–12**: Коллбэк вызывается асинхронно после того, как сетевой сокет перешел в состояние прослушивания (LISTENING). В терминал выводится сводка с адресом и текущим режимом работы (`NODE_ENV`).

### Строки 15–21: Обработка сигнала SIGINT (Ctrl + C)
```typescript
process.on('SIGINT', () => {
  console.log('\nОстановка сервера...');
  server.close(() => {
    console.log('Сервер успешно остановлен.');
    process.exit(0);
  });
});
```
- **Строка 15**: Метод `process.on()` подписывает функцию на событие ядра Node.js `SIGINT`.
- **Строка 16**: Печатает сообщение о начале процесса остановки.
- **Строка 17**: `server.close()` перестает принимать новые HTTP-запросы и ждет завершения имеющихся соединений.
- **Строки 18–20**: По завершении закрытия сетевого сокета выводится отчет и процесс штатно завершается с кодом успешного завершения `0` (`process.exit(0)`).

### Строки 23–28: Обработка сигнала SIGTERM
```typescript
process.on('SIGTERM', () => {
  console.log('\nПолучен сигнал завершения процесса...');
  server.close(() => {
    process.exit(0);
  });
});
```
- **Строки 23–28**: Аналогичный обработчик для сигнала `SIGTERM` от оркестраторов контейнеров или операционной системы, обеспечивающий бесшовную остановку процесса.

## 4. Схема жизненного цикла процесса

```
[Старт: node dist/server.js]
           │
           ▼
 [Импорт dotenv/config] ──> Считывание .env в process.env
           │
           ▼
    [createApp()] ────────> Сборка конвейера Express и DI-контейнера
           │
           ▼
    [app.listen()] ───────> Регистрация TCP-сокета в libuv (Event Loop)
           │
           ▼
[Ожидание запросов / Сигналов ОС]
    │                     │
    ├─ (HTTP Request) ────┴─> Обработка запроса контроллером
    │
    └─ (SIGINT / SIGTERM) ──> server.close() ──> process.exit(0)
```
