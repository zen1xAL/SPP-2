# Разбор файла [package.json](file:///d:/SPP/7sem/SPP/package.json)

Файл `package.json` – это манифест проекта, определяющий его метаданные, используемый модульный стандарт, зависимости и системные команды жизненного цикла.

---

## 1. Построчный анатомический разбор

```json
{
  "name": "spp-lab1-ssr-task-manager",
  "version": "1.0.0",
  "description": "Server-side rendered Task Manager with Express, EJS, and TypeScript",
  "main": "dist/server.js",
  "type": "module",
```

### Разбор параметров:
* `"name"`: уникальное имя пакета в экосистеме npm. Должно быть в нижнем регистре, без пробелов, с использованием дефисов (kebab-case).
* `"version"`: семантическое версионирование по стандарту **SemVer (MAJOR.MINOR.PATCH)**.
  * `1` (MAJOR) – мажорные обратно-несовместимые изменения.
  * `0` (MINOR) – новый обратно-совместимый функционал.
  * `0` (PATCH) – обратно-совместимые исправления багов.
* `"main"`: точка входа пакета при его импорте другими модулями или при запуске команды `node .`. Указывает на скомпилированный файл `dist/server.js`.
* `"type": "module"`: **Критически важный параметр для Node.js**.
  * По умолчанию Node.js работает в устаревшем стандарте **CommonJS** (`require()` и `module.exports`).
  * Флаг `"type": "module"` переключает весь проект на современный стандарт **ECMAScript Modules (ESM)**. Это активирует синтаксис `import` / `export`, работу с `import.meta.url`, а также поддержку асинхронного Top-Level Await (вызов `await` на верхнем уровне файла без оборачивания в `async` функцию).

## 2. Скрипты жизненного цикла (`scripts`)

```json
  "scripts": {
    "dev": "tsx watch src/server.ts",
    "build": "tsc",
    "start": "node dist/server.js",
    "typecheck": "tsc --noEmit",
    "test": "vitest run"
  },
```

### Как это работает под капотом:
1. `npm run dev` (`tsx watch src/server.ts`):
   * Утилита `tsx` (TypeScript Execute) компилирует TypeScript прямо в оперативной памяти «на лету» без записи файлов на диск через быстрый компилятор `esbuild`.
   * Флаг `watch` запускает файловый вотчер (file watcher) через системные уведомления ядра ОС (`ReadDirectoryChangesW` в Windows, `inotify` в Linux). Как только любой файл в `src/` сохраняется, процесс мягко перезапускается за доли секунды.
2. `npm run build` (`tsc`):
   * Запускает официальный компилятор `tsc` (TypeScript Compiler). Он читает конфигурацию [tsconfig.json](file:///d:/SPP/7sem/SPP/tsconfig.json), полностью валидирует типы и транслирует файлы из папки `src/` в готовый JavaScript в папку `dist/`.
3. `npm start` (`node dist/server.js`):
   * Запуск скомпилированного продакшн-кода стандартным интерпретатором `node`. Здесь нет накладных расходов на компиляцию TypeScript, код работает с максимальной производительностью движка V8.
4. `npm run typecheck` (`tsc --noEmit`):
   * Запускает компилятор в режиме валидации типов без генерации JavaScript (`--noEmit`). Идеально подходит для CI/CD конвейеров и быстрой проверки перед коммитом.
5. `npm test` (`vitest run`):
   * Запускает тестовый фреймворк `vitest`. Флаг `run` указывает завершить процесс после прогона всех тестов (без перехода в интерактивный режим наблюдения).

## 3. Зависимости времени выполнения (`dependencies`)

Это библиотеки, которые физически необходимы для работы приложения на сервере:

* `"dotenv": "^16.4.7"`:
  * Библиотека парсинга файлов `.env`. Считывает пары ключ-значение и безопасно внедряет их в глобальный объект `process.env`.
* `"ejs": "^3.1.10"`:
  * Движок серверных шаблонов (Embedded JavaScript). Компилирует EJS-разметку в чистые функции генерации HTML.
* `"express": "^4.21.2"`:
  * Минималистичный веб-фреймворк, реализующий обработку входящих HTTP-запросов через цепочки промежуточных обработчиков (Middleware Pipeline).
* `"multer": "^1.4.5-lts.1"`:
  * Промежуточный обработчик (middleware) для разбора потоков формата `multipart/form-data`. Позволяет серверу безопасно принимать бинарные файлы.
* `"uuid": "^11.1.0"`:
  * Криптографически стойкий генератор псевдослучайных идентификаторов версии 4 (UUIDv4), использующий системный генератор энтропии `crypto.randomUUID()`.

## 4. Зависимости разработки (`devDependencies`)

Эти пакеты используются только при написании, типизации и тестировании кода. В продакшн-сборку они не попадают:

* `"typescript": "^5.7.3"`: ядро компилятора TypeScript.
* `"@types/node"`, `"@types/express"`, `"@types/multer"`, `"@types/uuid"`, `"@types/ejs"`, `"@types/supertest"`:
  * Пакеты деклараций типов из репозитория DefinitelyTyped. Они содержат файлы `.d.ts`, сообщающие TypeScript точные сигнатуры функций сторонних библиотек, написанных изначально на JavaScript.
* `"tsx": "^4.19.3"`: CLI-утилита быстрого запуска TypeScript-скриптов с поддержкой ESM.
* `"vitest": "^3.0.7"`: современный тестовый раннер нового поколения, оптимизированный под ESM.
* `"supertest": "^7.0.0"`: библиотека интеграционного тестирования HTTP-маршрутов, позволяющая отправлять имитированные запросы к приложению Express без поднятия реального сетевого порта.

## 5. Тонкость языка и среды: Что означает символ каретки `^`?

В версиях зависимостей (например, `^4.21.2`):
* Знак `^` (каретка) разрешает npm автоматически обновлять библиотеку до самых свежих минорных версий и патчей, но **запрещает** обновление мажорной версии.
* `^4.21.2` означает: разрешена любая версия `>= 4.21.2`, но строго `< 5.0.0`. Это гарантирует отсутствие ломающих изменений API при повторном вызове `npm install`.
* Точные зафиксированные хеши и деревья зависимостей сохраняются в файле `package-lock.json`.
