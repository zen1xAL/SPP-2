# Автоматизированный процесс проверки кода (CI Pipeline)

Данный документ содержит разбор процесса автоматизированного контроля качества (Continuous Integration / CI), настроенного в репозитории в файле [.github/workflows/ci.yml](file:///d:/SPP/7sem/SPP/.github/workflows/ci.yml) в соответствии с требованием 5.

---

## 1. Назначение и триггеры пайплайна

**Continuous Integration (CI)** – это инженерная практика автоматической сборки и тестирования программного кода при каждом внесенном изменении.

Пайплайн запускается автоматически при следующих событиях:
- Любой коммит (push) в основную ветку `main`.
- Создание или обновление запроса на слияние (Pull Request) в ветку `main`.

---

## 2. Структура проверочных этапов (Quality Gates)

Пайплайн состоит из трех параллельных и последовательных задач:

```
[ Git Push / Pull Request ]
      │
      ├──► [ Job 1: typecheck-and-lint ] 
      │         Строгая проверка статической типизации TypeScript (--noEmit)
      │
      ├──► [ Job 2: automated-tests ]
      │         Прогон автоматических тестов (Vitest)
      │
      └──► [ Job 3: docker-build ]
                Тестовая сборка многоэтапного образа Docker (Dockerfile)
```

### Этап 1: Строгая проверка типизации (Typecheck & Lint)
- Проверяет соблюдение политики `strict: true` и запрета типа `any`:
  ```bash
  cd lab3
  npm ci
  npm run typecheck
  ```
- Гарантирует отсутствие синтаксических ошибок, несоответствия контрактов DTO и скрытых `null/undefined` падений.

### Этап 2: Автоматическое тестирование (Automated Tests)
- Запускает тестовый раннер `vitest`:
  ```bash
  cd lab3
  npm ci
  npm test
  ```
- Пайплайн автоматически проверяет:
  - Корректность работы трехуровневой ролевой модели (RBAC);
  - Защиту от подбора паролей (Rate Limiting и HTTP-статус 429);
  - Корректность генерации и валидации одноразовых токенов сброса пароля;
  - Форматирование структурированного JSON-логгера.

### Этап 3: Сборка Docker-контейнера (Docker Build Gate)
- Выполняет сборку многоэтапного Dockerfile:
  ```bash
  docker build ./lab3
  ```
- Проверяет, что компиляция фронтенда через Vite и бэкенда через tsc успешно завершается внутри легковесного контейнера Alpine Linux без конфликтов версий.

---

## 3. Локальная проверка перед коммитом

Для мгновенной локальной верификации разработчиком в `lab3/package.json` предусмотрен составной проверочный скрипт:

```bash
# Запуск полного локального цикла проверок:
npm run verify
```

Он последовательно выполняет строгий typecheck и автоматические тесты, гарантируя, что ни один дефект не попадет в репозиторий.
